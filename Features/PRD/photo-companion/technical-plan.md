# 需求与接入方案

目标是自用 Android 照片助手：夜间充电整理，优先原图下载，再实现新增照片双向传输；删除同步单独启用、单独验收。清理建议提供证据，由用户决定。

## 可行性与主要不确定性

本地整理、充电约束和夜间窗口可由 Android API 实现。WorkManager 是延迟容忍的任务调度，不能承诺每晚某分钟准时执行，当前每小时尝试、仅 00:00–07:00 开始。
依据：[Android 工作请求与约束](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)。

iCloud Photos 的主要风险是账号认证与非官方协议维护。CloudKit 官方文档描述的是应用自己的容器，因此不能把 CloudKit SDK 当作任意用户系统相册的访问接口。这里是基于官方容器边界的技术判断；当前没有实现一个可工作的 Android iCloud 客户端。
依据：[CloudKit 应用容器](https://developer.apple.com/documentation/cloudkit/enabling-cloudkit-in-your-app)。

ADP 和网页数据访问设置可能要求受信任设备批准，不能承诺无人工介入地永久同步，也不以关闭 ADP 作为默认解决方案。
依据：[Apple 网页数据访问](https://support.apple.com/en-au/102630)。

## 阶段与完成条件

| 阶段 | 实施 | 完成证据 |
| --- | --- | --- |
| 0 本地首版 | MediaStore、OCR、哈希、人工清理、夜间分析、MIUIX | 本轮已构建并在模拟器验证；实机整夜验证待补 |
| 1 账号与只读下载 | 使用 tools/icloud_probe.py 验证本人账号地区、2FA、图库访问；再实现 Kotlin 会话适配器 | 真账号验证、会话过期重登、读取原图并校验大小/摘要 |
| 2 新增双向传输 | 先下载再上传；持久化队列、分页游标、限流退避、重启续传 | JPEG/HEIC 样本往返，不重复上传、不静默转码 |
| 3 删除及恢复 | 独立删除意图日志、冷静期、冲突确认、两端回收站恢复 | 网络中断、另一端编辑、权限缩减、重装等场景不误删/回流 |

只读 Python 脚本是协议探针，不是手机后台服务。只有探针成功后才确定手机端认证实现方式；如手机直连不可维护，再评估用户已有 Mac/NAS 桥接。当前不引入必须常开的服务器。

## 同步数据模型与规则（待实现）

- 以 account + library + remoteAssetId 识别远端对象，以本地 URI + 内容摘要识别本地版本。文件名不作为唯一标识。
- 状态流：待上传 → 传输中 → 等待云端索引 → 校验完成；失败保留断点/幂等键。下载写入 MediaStore pending，成功校验后才公开。
- 权限收缩、分页未完成、网络失败和会话过期都不能解释成删除。只有明确用户意图才创建 tombstone。
- 导入来源标记防止安卓下载后再次上传。编辑版本保留为独立版本或提示冲突，不能仅凭修改时间覆盖。
- 会话凭证进入 Android Keystore 保护的私有存储；日志不写账号、cookie、密码或完整图片 URL。
- 视频和 Live Photo 需要资源配对、格式及元数据实测；首阶段不宣称支持。

## 清理策略

当前采用可解释规则：识别截图目录/名称，端侧中文 OCR 提取临时码与明确截止日期，年龄仅作为复查线索，文档关键词与用户保留名单保护，SHA-256 判定完全重复。OCR 全文不保存，仅保存分类信号与日期。

分批最多分析 80 张未缓存照片，未修改照片跨天复用哈希与 OCR 信号；日期规则可重新判定。相似图片、模糊图片与语义分类可后续加入，但不能凭模型分数自动删除。
